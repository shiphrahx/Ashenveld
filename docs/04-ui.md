## U1 — Make the layout responsive (Critical)

**Problem.** `.shell` in `src/App.module.css` is `width: 1100px; height: 660px` with `grid-template-columns: 295px 1fr 185px`. There are no media queries. On a phone the story column is squeezed to nothing.

### Three layouts

**Wide (1024px and up).** Three columns, fluid.

```css
.shell {
  width: var(--shell-w); height: var(--shell-h);
  display: grid; grid-template-columns: minmax(260px, 30%) minmax(0, 1fr) 232px;
  grid-template-areas: "art story side";
}
```

The story column caps its text at `--story-measure` and centres it. On a 2560px screen the shell stops at 1480×920 and the art column carries the extra width.

**Medium (720–1023px).** Two columns. The sidebar becomes a status strip above the story and a tab bar below.

```css
@media (max-width: 1023px) {
  .shell { width: 100vw; height: 100dvh; border: 0;
    grid-template-columns: 34% minmax(0, 1fr); grid-template-rows: auto minmax(0, 1fr) auto;
    grid-template-areas: "art status" "art story" "tabs tabs"; }
}
```

**Narrow (under 720px).** One column.

```css
@media (max-width: 719px) {
  .shell { grid-template-columns: minmax(0, 1fr); grid-template-rows: auto auto minmax(0, 1fr) auto;
    grid-template-areas: "art" "status" "story" "tabs"; }
  .art { height: 30dvh; }            /* banner */
}
```

### Component changes

- `SceneArt`: fills its grid area. `object-fit: cover` with `object-position` from the image's focal point (file 06, A3). On narrow screens it is a banner. When an outcome is showing on a narrow screen, shrink the banner to 18dvh so the text has room.
- `SceneView`: header row (scene title; act, chapter, day, time), scrolling story area, choices pinned at the bottom of the story area. Choices wrap. Minimum row height 48px. On narrow screens, if there are more than three choices, the choices list scrolls with the story instead of being pinned.
- `Sidebar` splits into two components:
  - `StatusStrip` (medium and narrow): Resolve bar, The Dimming word, day and time, coins. One line. Tapping it opens the full status as a sheet (stats, factions, class, trait).
  - `TabBar` (medium and narrow): Journal, Items, Map, People, Menu. Icons with text labels. Rest lives in the status sheet.
  - On wide screens `Sidebar` stays as one column and is 232px, not 185px.
- Panels (`Journal`, `Items`, `People`, `Map`, `Menu`): on wide screens keep the right-hand drawer, but give all five the same width (`min(520px, 92vw)`; the map `min(900px, 94vw)`). On narrow screens they are full-screen sheets with a header and a Close button at the top.
- `TitleScreen`: title size `clamp(40px, 11vw, 72px)`, letter-spacing `clamp(0.06em, 1.2vw, 0.18em)`. The word must never clip.
- `CharacterCreation`: see U13.
- `#root`: remove the fixed-height classes and the centring hack in `setRootClass`. One rule: `#root { min-height: 100dvh; display: grid; place-items: center; }`.
- The scanline overlay `.shell::after` is handled in file 05 (E5). Until then, limit it to the art area.

**Checks.** At 390×844 the first paragraph is fully visible without scrolling sideways, every choice is tappable, and every panel opens and closes. At 2560×1440 the shell is at least 1400px wide.
